# 部署与使用

当前应用 **1.3.2 / schema 5**。本指南对应当前源码；旧版本 ZIP、历史测试次数和早期联系人导入说明不是当前安装步骤。入口与文档目录见 [README](README.md) 和 [文档索引](docs/INDEX.md)。

## 1. 先理解系统做什么

系统推广《Use AI to Direct AI》，核心内容为“用 AI 指挥 AI，拓展个人能力边界”：规划 AI 提案，多顾问 AI 质疑与完善，人确定关键取舍，执行 AI 实施，再由不同 AI 结合实际结果检查。它是作者授权的方法主张，不是任何收件人的已验证成果。

研究保存公开网页证据 → 判断联系资格 → 模型提取客户简报 → 模型完整写 subject/body → 独立审核 → 程序硬校验 → 审核或发送队列。承诺发送短例子前，例子必须生成、审核并保存；对方接受后先兑现同一例子。章节推荐绑定一个章节，不能在回复中随意换成另一章。

默认不研究、不发信、不自动回复。启用后可长期运行，不需要保持浏览器或对话开启。每日10封是发送上限，来源、许可、预算、窗口或审核不足时可能少于10封。

## 2. 新安装

### 2.1 准备条件

- 一台 Linux 主机，建议至少 2GB 内存、5GB 可用磁盘；历史证据及备份持续增长，需定期查看磁盘空间。
- Docker Engine 与 Compose 插件、Git。Docker 安装可参考 [Debian 官方指南](https://docs.docker.com/engine/install/debian/)。
- 一个允许相关用途的发件邮箱，已开启 SMTP/IMAP；模型 API 与联网研究服务使用自己的账号。
- 默认一个管理员、一个邮箱、一个 Worker。SQLite 放本地磁盘，不使用 NFS 或多 Worker 并发处理同一账户。

```bash
docker --version
docker compose version
docker info
git clone https://github.com/watsonbkeel/book-mkt.git
cd book-mkt
bash deploy/setup.sh
```

脚本复制不存在的 `.env`、构建镜像、初始化数据库并启动 Web/Worker。首次显示管理员 `admin` 的随机密码，存入密码管理器；重复初始化不改现有密码。脚本不安装系统组件、不改其他服务。公开历史资源为空，不导入12人或任何其他真实名单。

密码、配置、邮件、来源和主密钥位于 `book-reader-outreach_outreach-data` 数据卷。不要把它们复制到公开仓库。`.env` 只保存绑定等运行设置，邮箱和模型密钥通过后台填写。

### 2.2 如何打开后台

默认只监听服务器 `127.0.0.1:8096`。在你自己的电脑上建立 SSH 隧道：

```bash
ssh -N -L 8096:127.0.0.1:8096 用户名@服务器地址
```

浏览器打开 `http://127.0.0.1:8096`。终端隧道需保持运行。

若使用 Tailscale，在服务器执行 `tailscale ip -4`，将你自己的地址填入 `.env` 的 `WEB_BIND_IP`，保持 `WEB_PORT=8096`，执行 `docker compose up -d --force-recreate`。通过同一 tailnet 打开 `http://你的Tailscale地址:8096`，并配置合适的 tailnet 访问权限。不要照抄他人的 IP，也不要改成 `0.0.0.0` 对公网暴露后台。

SSH 隧道或 Tailscale 内访问 HTTP 时，`OUTREACH_SECURE_COOKIE=false`。使用自有 HTTPS 反向代理时改为 `true` 并重建容器。`deploy/nginx-http.example.conf` 只是 HTTP 引导示例，没有为你配置证书；公网地址只能填写已配置的真实 HTTPS 根地址。

### 2.3 确认启动

```bash
docker compose ps
docker compose logs --tail=100 web worker
docker compose exec -T web python -m outreach.cli status
```

Web 与 Worker 都应健康；`/health` 返回应用版本。服务健康不等于邮箱投递或模型能力已验证。初始 Worker 即使发送关闭，只要配置了 IMAP，也会按小时执行收件同步。

## 3. 首次配置与启用

### 3.1 邮箱与发件身份

后台“配置中心”填写：

| 配置 | 如何填写 |
|---|---|
| 发件身份 | 真实姓名、发件地址、有权使用的真实邮寄地址；本项目当前书籍作者固定为 Huashan Chen |
| SMTP | 服务商提供的主机、用户名、应用密码；常见为465/SSL或587/STARTTLS，不自动降级明文 |
| IMAP | 服务商提供的主机、用户名、应用密码和邮箱文件夹；常见为993/SSL，当前不支持OAuth交互登录 |
| 自动回复验证 | 真实收件服务提供的可信 `Authentication-Results` 服务器标识；不要照抄示例域名 |
| 联系范围与发件认证 | 管理员核实服务用途、SPF/DKIM/DMARC及适用联系规则后确认 |
| 公网地址 | 可选的本系统 HTTPS 地址，用于退订页面；不是 Amazon 或外部资源站地址 |

密钥保存后不回显，留空保留。数据库中的凭证使用 Fernet 加密，主密钥在数据卷 `master.key`；备份包含解密材料，必须私密保管。

默认自动回复要求可信 DMARC、原发送线程和相同发件身份，Reply-To 不得换收件人。不通过交人工。连接测试只能验证认证/连接，不能证明投递、邮箱实际有信或任意来信都能自动回复。

当前程序页脚追加作者、公司（配置时）和邮寄地址；配置了公网 URL 才追加可见退订链接。此前按作者要求删除的固定“Book promotion … automated reading assistant”和“reply STOP”两行不会自动追加；来信 STOP/拒绝识别仍有效。其他运营者应审阅实际完整邮件和身份披露，不能仅依据旧文档推断页脚内容。

### 3.2 模型与研究服务

在“模型 Profile”配置实际可用的协议、HTTPS443端点、模型 ID、密钥、推理参数、输出预算和超时，并为以下六个任务指定路由：

| 任务 | 用途 |
|---|---|
| research | 搜索与网页信息提取 |
| brief | 从证据快照提取简报 |
| compose | 首封完整文案、原创短例子 |
| review | 首封、回复及例子的独立审核 |
| classification | 来信意图分类 |
| reply | 完整回复正文 |

支持 Responses、Chat Completions 和 Anthropic Messages。模型名及参数以账号与网关真实能力为准，不自动切供应商或降档。可让多个 Profile 引用同一密钥，也可使用独立密钥。全局 Key 为空时，只要各实际任务 Profile 完整，也可以启用。参数发送成功不等于服务商采用了参数。

作者当前生产部署的 classification/reply/review 使用 `claude-sonnet-5`（Responses，high）；这是该部署的选择，不是所有新安装均已配置或已获权限。新安装需要填写自己的有效 Profile。

研究可选供应商原生网页搜索，或 Brave 搜索再核验官网。普通聊天模型不自动具备搜索能力。来源抓取只跟随有限数量的实际同站 HTTPS 链接，邮箱须出现于原文；搜索摘要、模型猜测或 MX 记录不能单独证明联系人许可。详见 [模型路由](docs/MODEL_ROUTING.md)。

### 3.3 联系范围、研究国家与审核模式

默认 `consent_only`：有真实记录的联系许可并且其他资格检查通过才可发首封。管理员可确认 `us_business_public`：使用核实的美国公开业务来源，仍逐人检查邮箱原文、身份、职业相关性、地点、MX与来源限制。公开邮箱不是普遍营销同意。

`research_countries` 默认 `US`，后台输入逗号分隔代码，可选 `US,GB,DE,FR,ES,IT,NL,JP,BR,CA,MX,AU,IN`；英国用 `GB`。系统只在所选国家间轮换。非美国候选即使已入库，仍需单独记录许可；书籍在当地出版不等于可以向当地个人冷发。

| 模式 | 进入发送队列的条件 |
|---|---|
| review | 独立 AI 审核、程序校验通过后，再人工批准 |
| ai_review | 独立 AI 审核与程序校验通过 |
| automatic | 同样必须独立 AI 审核与程序校验，兼容名称，不跳过审核 |

首封主体80–120个英文词，不含链接；称呼和页脚另计。四项质量分均为越高越好，`reply_burden=5` 表示回复很省力。`quality_min_each=2`、`quality_min_mean=3.0` 是默认门槛；最多初稿加一次针对性改写，仍不通过暂缓。

### 3.4 预算与候选积累

| 项目 | 新安装默认 / 配置范围 |
|---|---|
| 活跃候选池 `queue_target` | 2000；5–2000，待核/可起草/排队合计 |
| 研究周期 | 240分钟；30–1440分钟 |
| 每批候选 | 最多8人 |
| 营销模型调用 | 每日60；可配置5–200，失败请求也计入 |
| 研究请求 | 每日3；可配置1–150，还受共享营销预算约束 |
| 来源抓取 | 每日80；可配置5–500 |
| 首封发送 | 每日最多10，默认间隔70分钟，不能配置低于61分钟 |
| 首封窗口 | America/New_York 08:30–19:30 |
| 自动回复邮件 | 默认每日20、间隔5分钟，每人滚动24小时2次、总计2轮 |

配置中的分类、回复生成和回复审核模型调用不计入营销模型每日额度；邮件次数、线程轮次及提供方额度仍有效。模型调用一次不等于生成了一封邮件，首封需简报、撰写、审核等多个请求。

研究预算有余、周期到期且候选池未满时继续累积。证据过期的未发候选归档留痕并释放名额；重新启用归档联系人必须重新核验。历史已联系和停发名单不计入活跃池但继续去重。详见 [候选池容量](docs/CANDIDATE_POOL_2000.md)。

`ku_enrolled_until` 默认 `2026-12-15`，留空表示未加入 KU；当前代码同时固定开始日为2026-09-15；按配置时区，开始日≤当日≤截止日期时可提及，到 **2026-12-16** 才因过期失效。书籍事实版本随可用状态变化，旧未发审核因此失效；不能把设置视为已经向 Amazon 实时核实。

### 3.5 启用顺序

1. 保存真实身份、联系范围、邮箱和模型路由，检查参数与预算。
2. 执行 SMTP/IMAP 连接测试；模型测试会付费，应由管理员明确发起。
3. 完成首次 IMAP 同步。首次从收件箱当前末尾建立游标，不自动重放所有历史邮件；手动同步同样受每小时门槛约束。
4. 使用自己控制且同意测试的收件邮箱，按 [真实验收清单](docs/上线前真实服务验收.md) 验证线程、回复和停止联系。先验证，不拿陌生人当测试对象。
5. 研究一批候选，查看证据、资格和生成全文。
6. 在总览启用“自动研究”，启用发送并勾选自动回复，按任务 Profile 缺项提示处理配置。

## 4. 持续运行时怎样处理来信

| 结果 | 例子与实际行为 |
|---|---|
| 停止联系 | 新回复“Nope”、明确拒绝或退订：保存停发记录，不回复确认，也不再次营销 |
| 自动回复 | 普通兴趣、问题、阅读进展、具体反馈：分类→撰写→审核各自持久化，审核通过后按发送保护排队 |
| 人工处理 | 未关联发件人、身份/线程存疑、敏感请求、意图不明、审核失败或超轮次：保留原因，由管理员判断 |

先分离引用，再判断新文字；“No, I don't have Kindle Unlimited. Where can I read it?”不能仅凭no判为拒绝。自动通知、退信等机器邮件另按既有规则处理，不进入对话循环。人工事项只影响该条记录，不暂停所有联系人。

后台收件列表与详情显示处理结果。人工接管需登录、CSRF及二次确认，原 AI 草稿保留为 `superseded`；收件人不能改，退订、旧来信及已尝试发送/uncertain 的回复不能通过接管重做。回复正文只允许固定图书链接，不发送附件。

自动化开关保存在数据库，服务重启后保留。Worker 优先处理来信阶段，研究与首封在预算和窗口允许时继续。没有“首封没回复就自动催促”的机制。细节见 [持续来信处理](docs/CONTINUOUS_REPLY_TRIAGE.md)。

## 5. 日常查看与排障

- **总览**：区分开关已开启与当前可发送。每日额度、间隔、窗口、收信健康、来源、审核、停发和熔断任一不满足，都不会外发。
- **候选**：查看资格原因、来源原文、档案及归档记录。不能把“候选”“可联系”“已联系”混为一谈。
- **队列**：`queued` 是排队；`accepted` 只是 SMTP 接受；`held` 要复核；`uncertain` 先查提供方日志，禁止自动重发。详情可下载实际发送 MIME，历史不会被后续编辑重写。
- **小时收信**：按上次尝试间隔≥3600秒；失败、积压或超过75分钟无成功同步会阻止外发。暂时故障恢复后自动继续，收信缺口和熔断需按实际证据处理。
- **停发**：网页/后台停发入库即生效；邮件拒绝要等下轮同步才能识别，不能声称实时收到邮件。已在 SMTP 提交中的消息无法撤回。
- **效果统计**：不跟踪打开、不推算销量/KENP/评论。阅读、练习和反馈只来自明确自述；CSV和邮件详情包含个人资料，不能公开。

在项目目录执行：

```bash
docker compose ps
docker compose logs --tail=100 web worker
docker compose exec -T web python -m outreach.cli status
docker compose exec -T web python -m outreach.cli qualification-report
# 暂停研究、发送和回复；收件同步仍由Worker按小时运行
docker compose exec -T web python -m outreach.cli pause
# 重置管理员密码并使旧会话失效
docker compose exec -T web python -m outreach.cli reset-password
# 私有备份（需要web容器正在运行）
bash deploy/backup.sh
```

`qualification-report` 只输出资格、原因、国家、候选池容量和调用用量，不输出邮箱。`status` 输出当前配置和统计；Worker 本地生成的 `STATUS.md` 不会同步到 GitHub 或 ChatGPT。

## 6. 升级、恢复与回退

每次升级保留旧镜像、`.env`、数据库和主密钥备份，核对端口/卷，避免两套 Worker 同时运行。**当前 `deploy/upgrade.sh` 只接受目标1.3.1，不能直接用于本仓库1.3.2。** 当前手动升级与回退步骤见 [升级指南](docs/UPGRADE_ROLLBACK_1.3.md)。

涉及旧 schema 的迁移会暂停自动化、暂缓未发稿，将未决发送记为 uncertain。部署后的最终检查必须包括原先启用的功能：获得运营授权、配置与收信健康通过后，在后台恢复需要的开关，不能把长期任务无声留在暂停状态。

备份含敏感材料；恢复到新的空目录/卷，保留原卷。先核对备份后实际发送的邮件，避免回滚数据库导致重复联系。不得执行 `docker compose down -v`。更换代码而不换 schema 时优先保留当前数据库；旧代码不兼容新 schema 时只能按指南恢复到隔离位置。

原生 systemd 安装见 [原生部署](docs/原生Debian部署.md)，与 Compose 二选一。

## 7. 验证边界和扩展方向

离线测试验证程序行为；真实模型预览只证明具体请求曾执行，不是文案外部批准；容器健康不是投递证明。当前及历史结果见 [测试报告](docs/TEST_REPORT.md)，报告保留各自时间、版本与不足，不将旧测试数当作当前状态。

想推广其他书籍、课程、软件或业务服务，先读 [扩展指南](docs/EXTENDING_TO_OTHER_DOMAINS.md)。当前代码仍绑定书籍事实、固定链接和章节；没有通用活动编辑器。新增领域需版本化事实、真实受众证据、可兑现的邀请资产、相应审核与回归，再在独立数据环境中验证。提高发信上限是另一个变更，需要单独评估规则、发送窗口、预算与邮箱能力；当前仍硬限制每日10封。
