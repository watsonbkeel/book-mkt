# 真实服务验收清单

本清单对应当前1.3.2/schema5，用自己的账号和明确同意测试的收件邮箱执行。每项记录时间、代码SHA、配置版本与结果；未执行写“未执行”。真实请求与邮件可能计费，先确认授权。mock通过不代表以下项目通过。

## 1. 启动与数据

- 两个容器健康，`/health` 报告预期应用版本，CLI status显示实际schema5。原端口、卷、账号、UID、停发记录和历史保留。
- 新安装自动化关闭；schema迁移后也应关闭，旧未发稿待核查、未决发送uncertain。仅代码重启保留配置，不应重置每日额度。
- 使用随机管理员密码登录，未登录/CSRF错误不能修改配置。Tailscale或SSH访问通路符合实际部署，不能公开暴露后台。
- 备份文件完整且私有；恢复演练使用新空卷，不覆盖正在运行的数据。

## 2. Profile与来源

- 六类任务路由配置完整；逐个记录真实请求的模型、协议、参数、超时和使用量，不用模型名称推断搜索/推理能力。
- 已授权的真实搜索须有提供方搜索记录，邮箱逐字出现在核验的官方来源。不能只凭搜索摘要/生成文本批准联系人。
- 检查默认US或所选国家列表。其他地区没有记录许可时应保持待核，不因为书籍在当地销售就放行。
- 2000人容量边界、伪造来源、去重和拒绝案例主要通过离线合成测试验证，不为凑边界导入真实陌生名单。

## 3. 自有邮箱的首封

- 管理员控制的测试联系人仍提供真实可核验的身份/页面及记录许可；不能为了通过资格检查伪造页面或跳过门槛。
- 使用review模式生成并查看完整邮件：正文80–120英文词、书名与Amazon出版事实准确、一个相关价值、一个可兑现邀请、无正文链接。
- 查看实际页脚和退订头。当前固定页脚不包含已移除的自动助理/STOP两行，不能按旧文档勾选“已披露”。
- 按时段/间隔发送一封，并在自有收件箱核实实际收到；后台accepted只证明SMTP接受，下载 `.eml` 对照。
- 若邀请例子，核对其已经生成/审核/保存；不得承诺整章文件或整本书。

## 4. 来信三种结果

- 正常回复原线程提问，等待下一次小时同步。分类、撰写、审核分阶段；结果合适且独立审核通过才排队。
- 让对方同意首信的例子或章节邀请，核对回复先兑现同一例子/章节，不固定要求Chapter15、不只发购买链接。
- “No, I don't have Kindle Unlimited. Where can I read it?”不能因no误判拒绝；报价、附件、意图不明等按现有敏感门槛交人工。
- 从原线程发送“Nope”或STOP：入库后停止联系、取消待发、0封确认回复。引用历史中的Nope不得当作当前拒绝。
- 未关联身份、Reply-To更改、可信DMARC不足应转人工；自动通知忽略；重复UID/Message-ID不得重复生成；第3轮自动往来转人工。
- 新来信取代旧待发回复。人工接管保留旧AI草稿及审核历史，不得绕过停发、固定收件人或已尝试发送限制。

## 5. 持续运行

- 收件同步间隔≥3600秒；手动按钮和重启不能缩短。首次建立游标不会重放所有历史。失败、积压或超75分钟无成功记录阻止外发。
- 普通临时健康故障恢复后继续；实际收件缺口/熔断须记录处理证据，不能为恢复发信直接清零。
- 原研究/发送/回复配置跨重启保存。单封人工事项不阻塞其他来信，研究积压不长期饿死回复阶段。
- 原发送额度和间隔跨重启持续；没有批量补发。SMTPuncertain先查服务商记录，不自动重发。
- 模型/搜索额度用完不能偷偷换供应商或降档；回复相关模型调用不占营销额度，但仍受邮件轮次、频率及提供方额度限制。

完成后由运营者明确决定启用哪些自动化。记录真实完成的项目；一次自有邮箱到达不能证明未来所有陌生邮件的投递率。
