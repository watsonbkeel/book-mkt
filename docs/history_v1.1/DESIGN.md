# Reader Studio v1.1 — 现有系统审阅与增量调整

## 已确认目的
用户要求现有Reader Studio收信从每2分钟改为每小时，并参考外部AI反馈审阅代码、调整可部署版本。保留每天最多10封首封、间隔至少61分钟（默认70）、SMTP+IMAP、可配置模型和来源可追溯后台。价格、Select、整体定位和付费推广不修改。只生成代码和部署包，不访问真实邮箱或发送真实邮件。

## 采用的增量设计
继续FastAPI/Jinja2、SQLite WAL和独立单Worker。不在每个Web进程内启动APScheduler，不引入Redis、Node构建或独立营销CRM。外部建议中的新版协议、搜索和安全需求按现有接口做增量扩展。

1. 固定3600秒收信，持久化尝试/完成时间，人工“收取”任务也共用节流。失败不立即重试。健康期限75分钟，任何已知失败、待检查大邮件/解析失败、积压未收完时停发；网页退订不等轮询。升级保留UID和邮箱验证状态但先暂停自动化，旧配置也生效。
2. 公开邮箱/业务证据/地域证据逐项保存；新增MX（含null MX和超时）核验、禁止收集/推销声明、系统角色邮箱过滤、同邮箱永久去重及同邮箱域名父子域365天首封冷却。不同品牌跨域的同一组织无法自动证明，不声称实现全组织去重。
3. 新候选用来源原文生成短邀请，不虚构读过作品、不声称获奖或千人效果、不自动引用未成年人案例。正文≤120英文词，合规页脚另计；固定书名/副标题/作者/Amazon说明，第一封不放营销链接。保留退出入口和自动助理身份，不伪装人工延迟。
4. 收信先规则分类：退订/拒绝停发不另回确认；报告类退信/自动通知/投诉不当成读者兴趣。真正可自动回复的必须匹配原Message-ID和收件认证；按地址兜底只能关联管理员查看，不能自动发送。自动回复默认总计2轮，现有3轮默认值升级为2，其他定制上限保留并受硬边界约束。
5. 增加可观测熔断：近24小时2个不同地址硬退信、1个可关联投诉、至少3个停发且在近7天已联系样本占比≥30%时暂停发送，需管理员附说明解除。投诉未接入提供方反馈环路，不能声称发现所有垃圾举报。
6. 分离SMTP已明确拒绝/临时拒绝/结果不确定。RCPT级5xx区分5.7/策略拒绝与地址拒绝；策略、正文、账号错误不能误判邮箱不存在。超时不自动重试。端到端SMTP exactly-once不可能保证，保留Message-ID与uncertain。
7. 增补待审编辑、分类筛选、发送计划/容量提示、风险记录、统计中退信/自动通知/停发/回复率说明、分类模型单独配置及Anthropic Messages+Brave兼容接口。模板知识库和Amazon入口保持锁定，资源链接先不自动加入。
8. 迁移自动化暂停、草稿重审；备份使用SQLite backup API而非复制WAL主文件；升级脚本先停止Worker、备份、再更新，不覆盖现有反代和其他业务。

## 未采纳或不作保证
- 9—17点无法安排10封且每封间隔>1小时：窗口容量显示实际值，不硬补发；保留可配置时区并建议用America/New_York处理夏令时。
- 不用“排除加拿大/欧盟”替代全球法律判断，也不把企业邮箱服务商视为允许冷邮件的保证。
- 不通过随机延迟、伪装人工、换域名/账号轮换规避过滤。
- 不把AI培训师/Newsletter全当成交互读者；欢迎联系的公开业务实践者优先，合作/报价请求转人工，不越权承诺渠道合作。
- 不用mail-tester分数或小样本经验承诺送达或固定回复率。

## 验收
保留v1.0的51项基线测试，修正其中150秒收信旧预期。新增时间旅行、升级、MX、同域、退信/投诉、人工编辑、模型兼容及注入防护测试；不把mock当真实SMTP/IMAP/模型联调。UI渲染及HTTP操作测试与生产浏览器/实机部署分开记录。
