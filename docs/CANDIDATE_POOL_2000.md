# 2000 人候选池

按作者要求，扩大候选积累容量，保留现有资格校验、预算、证据过期归档和发送限制。

- `queue_target` 通过现有 DEFAULTS/RANGES 校验：新安装默认 2000，可配置 5–2000。现有部署保留数据库设置，本次生产配置明确更新为 2000。
- 容量为非历史记录中 `candidate`（待核）、`ready`（可起草）、`queued`（排队）的合计，最多 2000，不是各状态各 2000。已联系、归档和停发记录保留，不占活跃候选池容量。待核硬上限同步提高到 2000。
- 研究批次逐人检查剩余容量，达到上限停止添加；预算足够且未满时，按既定研究周期继续发现候选。到期研究不再等待所有 ready 联系人起草完毕。来信回复仍优先。
- 自动复核可扫描整个 2000 人待核池，不再只扫描前 150 人；保留每人7天、全局5分钟冷却。
- 过期待核和从未尝试发送的ready/queued候选仍归档并释放容量，历史来源、去重和停发记录仍保留。归档或候选身份不代表可以发送，发送前仍需有效来源、地区/许可和审核。
- `qualification-report` 同时显示待核数量/硬上限和整个候选池数量/配置上限，不包含个人信息。
- 每日首封最多10封、间隔至少61分钟（当前70分钟）继续生效。本次没有提高每日发信限额，也未增加研究或模型预算。
