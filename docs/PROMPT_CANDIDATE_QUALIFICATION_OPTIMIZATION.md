# 候选人筛选规则优化开发提示词

将以下内容交给主对话执行：

请在当前 book-mkt 项目中实现候选人筛选规则优化。以最新工作树为准，先读取适用的 AGENTS.md、检查 git status/branch/HEAD，并复核现有研究、资格判定、联系人 UI、迁移和测试。保留现有用户修改，不回退代码，不重建项目。

目标是把“是否符合目标读者画像”和“是否具备联系/发送资格”分开。高相关候选人即使暂时缺少许可或证据，也要保留并显示具体待办；但画像匹配不能绕过现有联系许可、安全校验或发送门槛。

实现要求：

1. 搜索方向采用 10 次研究轮转中的 6/3/1 配比：
   - 6 次：科技及 AI 实践者，如软件开发者、AI 产品/工具构建者、技术教育者；
   - 3 次：参与儿童 AI 学习的成人教师、课程设计者、AI 素养教育者或家长教育者；
   - 1 次：相邻的业务流程、创作或小企业实践者。
   继续只研究成年人，不以儿童为联系对象；保留现有研究周期、国家范围和调用预算。

2. 为每位候选人分别记录并展示：
   - 画像匹配状态及原始来源证据；
   - 联系资格状态；
   - 未通过或待人工核验的具体原因。
   UI 应清楚区分“目标匹配”“证据待核”“需记录许可”“可进入发信流程”和“明确排除”。尽量复用现有状态和字段；如确需迁移，从当前实际 schema 版本升级并提供备份、回退说明。

3. 调整官方邮箱来源核验：
   - 邮箱仍须逐字出现在 HTTPS 官方来源页面中，禁止猜测邮箱；
   - 除个人/公司自有网站外，允许使用能核实该人员身份和当前任职关系的学校或雇主官方人员页；
   - 不再仅因个人主页域名与学校/雇主邮箱域名不同就判为不合格；
   - 搜索目录、数据经纪网站、无法确认身份关系的第三方页面不能作为替代证据；
   - MX、重复联系人、退订/抑制、来源拒绝营销、专用邮箱及业务域冷却等现有检查继续生效。

4. 调整地点和匹配引文的处理：
   - 允许官方机构页面中的当前职位/机构地点作为核验材料，但不能从客户所在地、活动地点、历史履历或模糊城市名推断候选人的当前业务所在地；
   - 地点有歧义时进入“证据待核”，不得自动放行为美国公开业务联系人；
   - 匹配引文未精确命中时，优先从已保存的原文快照重新提取或要求人工核验，不要因此丢弃高相关候选；
   - bio、fit_reason 和模型摘要仍不能冒充原始证据。写信和审核只能使用可追溯的来源快照。

5. 联系许可规则保持明确：
   - 13 个目标国家都可搜索并保留为目标匹配；
   - 非美国候选没有已记录联系许可时只能标记为“需记录许可”，不能自动冷联系或进入发送队列；
   - 个人邮箱仍需单独记录许可；
   - 美国公开业务资料只有在当前配置明确允许、地点及来源证据通过、且其他所有发送门槛满足时，才能进入发信流程；
   - 画像匹配、公开邮箱、MX 记录都不能单独代表联系许可。

6. 自动化只能为当前确实符合发送资格的联系人生成可发送队列项。待核验或待许可联系人不得被 Worker 自动改成 ready、排队或发送。可以在安全且不产生发送资格的情况下，为高相关候选提供仅供人工查看的研究简报；若现有架构做不到，保持其不自动生成首信，并在 UI 显示原因。

7. 增加统计，把候选人数量按画像匹配、证据待核、需记录许可、可联系、明确排除分类；多个拦截原因应分别计数并说明会重叠，不能把“待许可”报告成“不相关”。

8. 使用匿名 synthetic 夹具测试三类情形，不要把真实候选人的姓名、邮箱或资料写进源码、测试或公开文档：
   - 高相关美国学者，个人主页和机构邮箱域名不同：官方机构页能核实身份时，不因域名不同直接判不匹配；其余许可和地点门槛仍要检查；
   - 高相关美国教育者，地点摘录有歧义：保留为高相关，但需人工核验，不得自动发送；
   - 高相关非美国 AI 培训者，公开业务邮箱和工作来源有效但无联系许可：保留为高相关并标记“需记录许可”，不得进入发送队列；增加合成许可后再按其他现行规则判定。

必须回归现有 review、ai_review、automatic 三模式、联系许可、抑制/退订、来源快照、MX、发送前校验、研究周期、13 国搜索、小时收信、Tailscale 绑定及 Worker 安全测试。新旧规则冲突时，只替换本任务明确涉及的筛选行为，不削弱其他安全限制。

所有验证只用隔离临时数据库、synthetic 夹具和 mock 服务。不要读取或连接生产收件箱/联系人库，不发真实邮件，不调用未经授权的付费 API，不做生产部署，不删卷，不 push、merge 或发布。完成后报告代码改动、迁移与回退方案、测试结果，以及仍需人工核实的边界。
