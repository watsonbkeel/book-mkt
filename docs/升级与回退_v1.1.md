# Reader Studio v1.0 → v1.1 升级与回退

## 已装1.0：使用同一数据卷，但不要覆盖原代码

标准Compose项目名是 `book-reader-outreach`，卷仍为原来的 `outreach-data`。新版本不改变项目名、端口或卷名；升级中的schema迁移为1→2。

上传并解压新ZIP到不同的源码目录，例如：

```bash
cd /opt
unzip Book_Reader_Outreach_v1.1.zip
cd Book_Reader_Outreach_v1.1
bash deploy/upgrade.sh /opt/Book_Reader_Outreach_v1.0 --confirm-pause
```

脚本按顺序做：核对默认配置 → 保留旧.env → 构建新镜像 → 停旧Worker和Web → 用旧版本CLI创建SQLite在线快照及主密钥备份 → 导出私有备份到新版`backups/` → 运行新版迁移 → 再次确认所有自动化关闭 → 启动新版。

只支持默认1.0.0 Compose布局。不接受不同项目名、Compose覆盖文件或环境覆盖；有这些情况先按下面手工流程核对真实卷。升级脚本已做shell语法及假Docker命令编排测试；本次环境没有Docker引擎，未声称已经在Debian容器环境执行成功。

**脚本失败时旧服务可能保持停止；不会为了恢复流量跳过备份或自动重新发信。** 检查终端错误。若备份导出失败，临时容器可能仍保留，仅在核实备份状态后删除；不得删除真实数据卷。脚本从不执行`down -v`。

## 迁移保留与改变

保留：原数据库、Fernet密文/主密钥、管理员、全部联系人、已发邮件正文/MIME/Message-ID、收信UID游标、历史导入和停发哈希。

新增：邮箱域名列、MX证据版本、搜索种子记录、投递风险事件、模型/用途日志字段。老来源证据仍保留，但没有v2来源验证的公开候选不得自动继续发；可在联系人页面重新核验。

改变：全部自动化暂停；旧draft/queued转held，需核对短文案/来源后再批准；旧sending转uncertain，不自动重发。原默认3轮自动回复改为2；已人工设置为其他值的记录保留，在后台复核。其他已有发送时区/窗口/密钥不被新默认值覆盖。

旧待审邮件若没有新版完整书名/副标题或超过120词，可在邮件详情编辑到新规则，保存为draft后再批准。未发送公开候选必须先重新核验来源与MX。不要通过删除邮件记录来重新生成首封。

## 自定义Compose配置的手工流程

1. 在旧系统执行CLI `pause`，随后停止旧Worker和Web；确认只有这一份Worker拥有发送任务。
2. 核对`docker inspect`中的真实数据卷名，记下旧镜像tag和.env。不要凭路径猜卷。
3. 用仍保留的旧镜像、相同卷，执行`python -m outreach.cli backup --output /tmp/pre-upgrade.zip`，并导出到只有管理员可读的主机目录。备份包含密钥，不可公开。
4. 在新源码目录构建1.1镜像，明确绑定原来的卷；保留端口及HTTPS设置。
5. 启动一次 `python -m outreach.cli init` 完成迁移，不带`--seed-history`；再执行`pause`。
6. 启动新Web，核对健康、旧联系人数量、已发记录、退订名单、IMAP游标；然后启动新Worker，仍不启用外发。
7. 自有邮箱验收后，才在网页重新启用。

## 原生systemd升级

先 `systemctl stop outreach-worker outreach-web`。用旧虚拟环境执行CLI备份到私有目录，另存原源码及`.venv`。部署新源码与依赖时不要复制或覆盖 `/var/lib/book-reader-outreach/master.key`；继续使用同一个数据目录，执行新CLI `init` 和 `pause`，再启动两项服务。先验收，不自动开关发信。

## 回退

不能用1.0代码直接打开schema2数据库。回退前停止所有Worker；用升级前ZIP恢复到全新空数据目录/空卷，绑定旧代码/旧镜像；恢复命令会保持自动化关闭。必须人工核对备份之后可能发生的真实发送、回信和退订差额；旧备份不是撤销邮件的方法。没有核对差额前不得启用发送。

## 新装用户

没有部署1.0的直接按README运行`bash deploy/setup.sh`，不使用升级脚本。首次安装随机密码、空凭证，所有自动化仍关闭。
