## 2. 明确替换两个旧文案契约，其余安全规则保留

根AGENTS.md、domain.validate_initial、composition模块、旧测试中仍存在这些旧要求：
1. 强制每封首信完整副标题；
2. 强制模型选择字面引文和预设文案样式。

用户已确认的新设计在本轮明确替代这两项实现约束：首信自然出现主标题与Amazon出版说明即可，作者身份在最终署名明确呈现；完整副标题仍保留于书籍元数据。允许自然转述已核事实和明确标注的应用设想，不强制引文、不强制四词框架、不强制固定开场。

同步更新AGENTS.md的这两项契约、当前设计文档和相关测试。旧历史文档标明历史用途，不改写其当时结果。不要为兼容旧断言而把弱模板又塞回新流程；也不要借此删除安全测试。

继续保留：
- 每当地日最多10封首封，默认70分钟、最低61分钟，重启不清零、不补发。
- 每小时收信：尝试间隔至少3600秒，手动与重启共享时间戳；75分钟收信健康和发现错误后的外发阻断不削弱。
- 默认不启用研究、发送或自动回复；新装默认review。迁移不能自行启用生产。
- 源文/邮箱/MX/地域/许可、同邮箱去重、业务域冷却、停发哈希与来源年龄检查。
- 拒绝/退订/投诉/退信、可信线程、Reply-To、DMARC、自动通知处理、自动回复轮次上限。
- SMTP uncertain不自动重发、Worker锁、短事务预占、发送前最后检查。
- 不让模型选择收件人、抄送、附件、时间、任意URL或删除停发记录。
- 真实身份、公司邮寄地址、自动助理披露、退出方式；固定页脚准确添加一次。
- 不索评、不五星、不利益交换、不承诺未经批准的整本/整章附件，不改书价、Select、Amazon页面和总体定位。
- HTTPS/SSRF/DNS绑定、登录/CSRF、凭证加密、输出转义、私有备份及匿名/保留期规则。

## 3. 在研究阶段留下可用证据，再生成客户简报

复用Researcher和SourceFetcher，不另造无限抓取链。新增受限证据片段存储/快照：source_id、原URL、抓取时间、内容指纹、与此候选有关的原文片段。为单来源、单候选和每任务设可配置上限并受系统预算约束。

选取真正描述此人/业务/项目的段落，而非仅邮箱旁70字符或10—25词fit_quote。不要无限保存整站，也不要将所有原文塞进每次模型请求。旧联系人缺证据时，允许通过明确的研究/重新核验动作补齐；写信和回信模型不能自行打开来源，更不能访问来信中的URL。

`bio`与`fit_reason`是模型整理结果，不因已经存入contacts就变成已核事实。客户简报至少区分：
- verified_facts：陈述、source_id与原文；
- relevant_work_topic：一个真实的工作主题；
- possible_use_cases：可能应用本书的方法设想，不伪装成此人的痛点/成果；
- unknowns：不知道的事；
- 已批准的书籍价值、相关章节摘要和当前可兑现的邀请动作。

source_id存在、原文片段存在不等于语义必然支持全部陈述；语义存在疑问时转人工。资料不足就held/review_required，不退回只换名字的通用营销信。

网页、模型整理文本和邮件均是不可信数据，不能改变系统指令、许可、收件人、模型端点或安全规则。

## 4. 模型完整写邮件，程序不再替它填正文

模型输出完整`subject`、不含称呼/署名/页脚的`body`，及简短核验元数据：recipient_claims、book_fact_ids、selected_chapter_ids、offered_next_step，必要时关联asset_id。不得索取或保存私有思考过程。

文案目标：
- 主文以80—120英文词为目标，上限120；统一并测试计数规则。称呼、署名和固定合规页脚另计，不以挪段落到页脚规避限制。
- 一个邮件只讲一个与该读者有关的价值和一个容易回复的下一步。
- 让读者理解：与一个AI形成计划，用其产出指挥其他AI制作和检查，人保留重要决定。不要写成AI无人自主互相命令。
- 不强制出现Think → Write → Build → Check、完整副标题或Goal/Acceptance术语。
- 不再固定拼接OPENINGS/BENEFITS/SUBJECTS、KU段落、反馈请求；这些旧值只可为历史兼容保留，不可作为新生成兜底。
- 自然出现Use AI to Direct AI及已在Amazon出版；主文无购买或资源URL，合规退订链接由程序页脚添加。
- 不假装作者人工读过对方文章、建立过关系；不编文章、业绩、保证收益、学生效果或对方缺陷。
- 可用what if/could等明确表述教学应用设想，但不得在其他句子里又将其当作已发生事实。
- 不强制要求购买、读完整本、试练习、反馈四项同时完成；首封不必提KU。
- 不隐藏自动助理身份、不伪装Re:/Fwd:、不靠随机延迟伪装手工操作。

Bradley的“AI不只写跟进邮件，也可能帮你做跟进工具”仅是质量方向示意，不是全员通用句，更不是本书已有真实客户案例。

程序统一组装称呼、正文、署名及固定页脚；最终发件内容和MIME保留快照，历史正文永不由新模板重新计算。模型不同的合法正文必须能不失真地保留到队列。

## 5. 扩展现有审核与三模式，不保留绕过新检查的路径

复用并重构现有review_initial/review_reply，清除“新正文必须等于旧render_initial”的依赖，改为版本化草稿契约。检查调用必须读取原始证据、书籍事实、邀请资产和整封邮件，不仅检查写信模型自报的claims。

区分硬性失败和质量建议：事实/许可/退订/禁止内容/不可兑现承诺是硬门槛；相关性、收益具体性、自然度、下一步负担是质量维度。分数不是回复率预测。检查不通过最多触发一次定向重写，即初稿加一次修订；检查本身失败/超预算/无证据则停发，不因每日额度未满放行。

本次明确的新模式语义：
- review：AI检查与程序硬校验通过后仍需人工批准；检查失败保留held。
- ai_review：AI检查与硬校验通过后排队，省去逐封人工点击。
- automatic：兼容保留旧枚举及用户配置，但新文案也必须通过相同AI检查和硬校验；页面清楚说明，不再表示“跳过AI质量检查”。

这是新生成流程的验收要求，不是声称旧automatic当时已经具备AI检查。迁移时全体旧待发保持暂停，不让切模式释放旧草稿。人工按钮不能批准缺证据或硬检查失败的草稿。人工手写回复也保留固定政策、收件人和停发门槛，并明确其审核责任；不能借改kind把AI草稿伪装成人工输入绕过新审核。

审核凭据绑定：草稿revision、subject/body哈希、相关证据快照哈希、书籍事实/政策版本、资产版本、检查profile版本、生成合同版本，以及影响发件内容的身份/页脚配置摘要。模型配置更新如何使既有草稿转待复核须可见，不静默复用失效批准。

编辑、修改来源、改正文后，旧活动审核/人工批准失效，保留历史审阅记录；提供真正可执行的“重新检查”任务入口。不要让编辑后的邮件因为唯一键或旧render约束永远无法再次审核。

API调用在事务外。回写审阅结果使用expected_revision/hash比较更新，避免审旧稿批准新稿，或旧失败覆盖新编辑。发送预占事务重新读取当前模式、停发、来源、版本、最新来信与检查状态；出现变化转held，不在SMTP前临时让模型修改已批准文字。

## 6. 首封承诺与回复一体化

重构Engine.process_inbound中的interested/reading/feedback固定回复，及answer_question/queue_reply的任务路由，不只改首信。

每封首信保存其实际offered_next_step及资产版本。只有原创教学短例子已生成、通过检查并保存在本地，首信才可承诺发送该短例子。短例子不是书中原文、真实客户效果证据、免费书或为客户开发完整产品的承诺。

收到明确愿意看例子的回复后，先在邮件正文交付对应已批准例子，再按需要推荐章节和固定Amazon入口。不能改成“先买书/KU才能得到承诺的例子”。资产缺失、版本不匹配或对方问了另一个问题时，转人工或重新生成草稿检查，不自动许新承诺。

未承诺例子的首信无需强行添加例子。用户已开始阅读时不要重复推销和无限追问。退订、拒绝、自动通知、复杂商务/版权/附件请求仍优先处理并停止或转人工。

同一inbound_id只允许一个当前可发送回复；held的合法重做应使用安全的版本化更新，不能被唯一键卡死，也不能删除实际发送历史。生成期间有新来信时旧回复必须失效；真正发出前再次确认不是被新消息取代的回答。两轮自动回复上限维持。

## 7. model profiles、任务路由与协议

用可复用profile管理独立协议、Base URL、加密密钥引用、模型ID、effort/thinking策略、生成预算、超时与工具能力。任务至少research、brief、compose、review、classification、reply，可多任务共用一个profile。

兼容现有API入口与用途日志：
- personalization → compose；
- initial_review/reply_review → review，但日志保留审核目标；
- classification → classification；
- answer_question及各实质回复 → reply；
- native research、Brave提取、research_continuation → research任务/子用途。

迁移现有全局配置为显式Legacy profile；classification_model可形成同端点的分类profile覆写，不能丢弃现有值。首次部署和迁移都不能自动选新供应商或增加付费调用。

Luna medium用于研究/简报、Luna low/medium分类、Sonnet high写作/回复是待管理员确认的预设，不是模型品质或账号能力的结论。未配置Sonnet不得偷偷回退或使用别的密钥；允许清楚标识的单模型兼容方式。

按官方协议与实际网关能力分别构造Responses reasoning.effort、Chat reasoning_effort、Anthropic适用的effort/thinking字段。default/omit与none是不同含义；low/high/max/xhigh等不能被认为跨供应商预算等价。支持的枚举依模型/端点而定；未知网关可记录管理员选择为未验证，但不伪造“已生效”。不静默丢参数、不自动将max降为high。

保留Anthropic原生搜索/pause_turn结果匹配、Brave、send_max_tool_calls等可用路径。研究工具不能被复制到写作、审核、分类或回复请求。跨端点修改不能顺手把旧供应商密钥发给新主机；继续HTTPS443、DNS绑定/SSRF限制，不顺便支持任意内网API。

每个任务可配置生成预算、超时，受系统最高值及调用数上限约束。所有生成、审阅、修订、续接、失败请求都入预算。保持现有daily_api_calls/daily_research_calls/daily_fetches等，不为填满每天10封自动提高上限。

处理incomplete、length/max_tokens、无可见正文、坏JSON、429、超时、错误工具结果；失败关闭。连接测试按profile显式触发，提醒可能计费；参数预览纯本地不联网。

日志包括任务/草稿ID、profile版本、请求模型、响应报告模型（若有）、用户设置及实际发出effort字段、预算、耗时、usage和结束状态、prompt及材料哈希；不记录密钥、敏感请求头、原始思考块。

“参数已发出”“HTTP成功”“提供方明确返回采用参数”分开显示。响应没报告的内容保持未确认。

## 8. 修复本仓库特有的失败状态问题

Worker.tick在草稿失败时会执行：
`update_contact(..., state='candidate', permission_note='草稿失败：...')`。

这把运行错误写进许可证据字段，可能覆盖真实permission_note，而Engine.eligible对consent路径只检查该字段非空。必须把生成/审核失败原因写到独立运行状态/草稿/任务错误字段，不能写入、替换或制造许可记录。旧错误文字不应被自动修成许可；无法恢复的证据缺口标人工复核，不推断同意。

增加回归：有真实许可的联系人在生成失败后许可全文不变；无许可者不会因非空失败提示成为consent；人工重新核验不能绕过停发。

高推理会增加单次延迟。现Worker.tick同步串行处理任务，Compose stop_grace_period=120s。给每次tick及整个生成链设置总时限/调用上限，或者拆成受控持久任务继续，不在Web请求或SQLite写事务内长时间等待模型。保持单发送Worker和下次tick优先收信；不通过延长75分钟健康或加快IMAP轮询掩盖问题。

增加慢模型、停机、重启的mock测试：心跳/健康状态准确，过期收信不发送，取消不会生成重复邮件，不遗失退订，不重跑uncertain。
