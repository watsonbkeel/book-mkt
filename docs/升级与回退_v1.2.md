# Reader Studio v1.0/v1.1 → v1.2 升级与回退

## 尚未部署
解压新包，执行README中的`bash deploy/setup.sh`。随机密码、空凭证、默认暂停+review；新装美东08:30–19:30/70分钟，收信每小时。setup自动导入已确认12名历史联系人；不需要重复点击导入，重复导入也不会重复计数。

## 已用标准Compose部署v1.0或v1.1
旧目录、.env、数据卷不能覆盖或删除。新包放单独目录；以下示例旧版为v1.1，v1.0按真实旧目录替换最后一行参数：

```bash
cd /opt
unzip Book_Reader_Outreach_v1.2.zip
cd Book_Reader_Outreach_v1.2
bash deploy/upgrade.sh /opt/Book_Reader_Outreach_v1.1 --confirm-pause
```

脚本只接受VERSION为1.0.0或1.1.0、默认Compose项目book-reader-outreach、没有覆盖文件或项目环境覆盖的部署。新镜像标签1.2.0，项目名和卷名不变。脚本先构建再停旧worker/web，用旧镜像创建SQLite在线快照和master.key备份、导出到新版私有backups目录，才执行新版本init迁移和pause，再启动。备份失败时不跳过，不自动恢复发信。不要执行`down -v`。

脚本有离线假Docker编排测试；本次没有Docker引擎，不能据此声称已在你的Debian执行。自定义改过卷、项目、端口、.env或Compose布局时按下列手工步骤核对。

## 数据迁移行为
schema1/2迁移到3；只执行一次。保留密钥和所有凭证密文、联系人/退订哈希、已发正文与Message-ID/MIME、收件UID游标、实际发送时间和历史记录。所有自动化关闭；旧draft/queued→held，sending→uncertain，不自动重发；旧待执行job失败收口。

**旧时区/时段/间隔明确保留。** 缺少持久字段的旧库也补成旧默认HK09–22，而不是悄悄解释为新默认。启动后去配置中心，确实要用美东时勾选确认、点击“应用美东预设并暂停”；这只改时区/时段/间隔并暂停，不修改每日额度、账户/凭证或书籍。

公开来源验证升级为v3，原记录不删除，但重新核验前不得继续自动发；在联系人页点重新核验。历史已经联系过的人不能靠重新核验变成新首封。被held的旧草稿可以按新文案规则编辑后重新批准，消息历史不删；不要求给原收件人再发一封新邀请。

## 手工/原生升级
1. 暂停并停止旧worker与web，确认没有其他机器或另一worker连接同一数据卷。
2. 用旧版本CLI `backup --output /私有目录/备份.zip`，另留旧源码、.env和镜像标签；备份含解密密钥。
3. 在新源码目录构建1.2，明确绑定旧卷或OUTREACH_DATA_DIR。原生部署先安装同一requirements依赖，不覆盖master.key。
4. 执行一次新CLI `init`，不要使用`--seed-history`重播来源；再执行`pause`。
5. 先启动web，核对健康1.2.0、联系人与已发数、停发名单、UID及旧设置，按需应用美东预设；再启动worker，仍保持暂停。
6. 自有邮箱验证发送、小时收信、关联回复及退订；实际模型和搜索按选定模式测试。之后明确启用。

## 回退
不能用v1.0/v1.1打开schema3生产库。停新worker/web，用升级前备份恢复到新的空数据目录/空卷并绑定旧镜像；恢复后保持暂停。核对备份后实际发送、退订和回信差额，不能用回滚丢掉停发记录或把发送额度倒退。恢复数据不是撤回邮件。没有差额核对不得恢复自动化。
