# 持续运行与来信三种处理结果

本次任务：保留现有 Engine、ReplyPipeline 和 Worker，完善来信判断与后台说明；用隔离数据库和 mock 回归后部署，按作者本次授权恢复持续研究、发送和自动回复。无需新 schema、独立队列或新供应商。

1. **停止联系**：明确拒绝邀请（如独立新文字 `Nope`、模型识别的 `No thanks`）、退订或投诉进入停发名单，不生成确认或追问。保留来信与审计记录，不能把拒绝删除成“未回复”后再次营销。
2. **自动回复**：兴趣、普通问题、阅读进度和具体反馈由已配置的 reply Profile 撰写，review Profile 独立审核。生产按作者要求使用既有 `sonnet-write`（`claude-sonnet-5`，Responses）完成分类、撰写与审核，保留参数和密钥引用。初稿加至多一次改写；仍不通过转人工。
3. **人工处理**：身份或线程不明、Reply-To 不符、DMARC 验证不足、敏感请求、意图不明、模型失败、审核失败或超出自动回复轮次。保留现有人工接管操作；单封异常不暂停其他合资格联系人。

先分离引用，再判断新文字。`No, I don't have Kindle Unlimited. Where can I read it?` 是阅读入口问题，不能仅凭 `no` 停发。自动通知、退信等机器邮件沿用原有专门规则，不生成回复；自动通知本身不表示拒绝。

分类记录包含程序推导的 `handling` 和 `reply-triage-1` 版本，不能由模型任意指定发送动作。分类版本加入回复审核绑定，旧版本的未发回复须复核。首信绑定不因这一分类版本变化而失效。后台收件列表与详情展示实际处理结果。

Worker 每周期先按原小时门槛同步收件，再把新来信加入既有持久化回复任务；回复阶段优先于普通模型任务及研究。按 inbound_id 去重，重启后仍继续原阶段，避免研究积压让来信永久等待。仍然每阶段最多一次模型调用。

## 长期运行

启用后的设置保存在数据库中，容器重启保持设置。IMAP 临时失败或健康过期时，原发送门槛阻止外发；收信恢复且其他门槛满足后自动继续。单封人工事项不关闭全局自动化。涉及 schema 的升级仍按安全迁移暂停，发布流程在已获作者运行授权、配置和健康检查通过后恢复；不能盲目恢复未核查的安装。

每日首封最多10封、至少61分钟间隔（当前70分钟）、每小时收信、75分钟健康门槛、停发、SMTP uncertain 不重试和每人最多2轮自动回复保持。回复相关模型调用不计入营销模型额度；既有邮件频率和轮次限制仍有效。开启自动化不保证每日能达到10封。

验证：全套 pytest、compileall、合成收件页面检查；真实部署只检查容器、任务配置与健康状态。mock 分类测试不能证明真实模型对任意语义均能正确分类。
